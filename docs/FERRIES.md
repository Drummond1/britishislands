## 1. Data model

Mirrors the `data/galleries.json` pattern: lazy-fetched on the first island click, joined to islands client-side via `terminal.islandId`. Three companion JSONs avoid bloating the 8 MB `islands.json` first-paint.

```
data/
  ferries.json            # routes, schedules
  operators.json          # operator metadata
  ferry_terminals.json    # canonical terminals (shared across routes)
  ferries_manual.json     # hand-curated long-tail (merged into ferries.json at build)
  causeways.json          # tidal / bridge access (not a ferry, but same UX)
  ferries_stale_report.json  # auto-generated by refresh_ferries.py
```

Route record shape (live in `data/ferries.json`):

```json
{
  "id": "calmac-oba-cra",
  "operatorId": "calmac",
  "operatorRouteCode": "OBA-CRA",
  "name": "Oban — Craignure",
  "terminals": {
    "from": { "terminalId": "term-oban",      "islandId": null },
    "to":   { "terminalId": "term-craignure", "islandId": "isle-of-mull" }
  },
  "type": "car-and-foot",
  "seasonality": "year-round",
  "frequencyBand": "several-daily",
  "durationMinutes": 45,
  "vessel": ["MV Isle of Mull", "MV Loch Frisa"],
  "vesselWikidata": [],
  "bookingUrl": "https://www.calmac.co.uk/route/oban-craignure",
  "timetable": { "source": "calmac-gtfs", "validFrom": "...", "validTo": "...", "weekly": [...] },
```

## 3. Data sources

### OSM (Phase 1 — 156 routes)

- `scripts/fetch_ferries_osm.py` issues Overpass `relation["route"="ferry"]` queries inside the dataset bbox.
- Terminals are extracted from member nodes tagged `amenity=ferry_terminal`. Where the relation lacks an explicit terminal tag, the script falls back to the first/last node of the first/last way.
- Each terminal is matched to the nearest island in `islands.json` within 1 km (Haversine). `EXTRA_OPERATOR_ALIASES` maps OSM `operator=*` strings to canonical operator IDs.
- ✅ Cheap, ToS-clean, covers ~45 % of the corpus.
- ⚠ Geometries are indicative only — render as dashed polylines with an "indicative route" caption.

### GTFS (Phase 2 — 141 routes)

- `scripts/import_calmac_gtfs.py` (now also runs for NorthLink, Pentland, Orkney, SIC, Argyll & Bute, Ulva, Skye, Highland) downloads a GTFS `.zip` from Traveline Scotland / BODS.
- Filters by agency name, joins `routes / trips / stop_times / stops / calendar`, reconstructs the `timetable.weekly` shape, and matches GTFS stops to existing terminals by name + 250 m proximity. New stops become new terminals when no match is found.
- ✅ Single source covers most Scottish car-ferry volume.
- 🔁 Re-fetch whenever `validTo` is within 30 days (Phase orchestrator nudges this in `ferries_stale_report.json`).

### Manual curation (Phase 4 — 50 routes)

- `scripts/seed_ferries_manual.py` defines hand-curated routes for operators where scraping is forbidden or impractical (mostly England, Wales, NI, IE, Crown Dependencies).
- Each manual route carries `frequencyBand` + `timetable.notes` rather than a full weekly grid — these operators publish weather- and tide-dependent schedules that don't fit a GTFS-style table.
- `scripts/merge_ferries.py` overlays manual records onto the OSM/GTFS-derived set, with manual entries having priority on every field except where a GTFS schedule is genuinely newer.

### Wikidata + Wikipedia (cross-link)

- `scripts/enrich_ferries_wiki.py` adds operator Q-IDs and Wikipedia URLs. Validation pass after the first run caught and corrected 15 hallucinated Q-IDs (a Wikidata search-result confusion across similarly-named operators). All operator Q-IDs are now hand-verified.

### UKHO tide windows / OS bridges (Phase 6d)

- `data/causeways.json` carries 11 tidal-causeway / bridge entries (Lindisfarne, St Michael's Mount, Davaar, Cramond, Eriskay, etc.). These render in the same "How to get there" block as ferries but as a separate `_renderCausewayBlock`.
- Safe-crossing windows come from the UKHO Admiralty Tidal Stream Atlas where available; otherwise the operator-published table (Northumberland County Council, Cornwall Council).

## 4. Refresh cadence

`scripts/refresh_ferries.py` is the orchestrator. Designed to run monthly (e.g. via cron or GitHub Actions). Stages:

```
osm       -> scripts/fetch_ferries_osm.py
gtfs      -> scripts/import_calmac_gtfs.py × 10 Scottish agencies
manual    -> scripts/seed_ferries_manual.py
merge     -> scripts/merge_ferries.py
names     -> scripts/enrich_terminal_names.py
drivetime -> scripts/compute_drive_times.py   (slow; off by default)
seo       -> scripts/generate_ferry_landing_pages.py
```

After every run it writes `data/ferries_stale_report.json` listing every route whose `lastVerified` is older than **180 days** (`STALE_DAYS_HARD`). The UI surfaces this:

- Routes ≤ 180 days → green `.ferry-card__verified` badge: "Verified 2026-05-11".
- Routes > 180 days → orange `.ferry-card__stale` badge: "Stale (verified 2025-09-12) – re-verify with the operator".

Example invocations:

```bash
python3 scripts/refresh_ferries.py                       # full pipeline minus drivetime
python3 scripts/refresh_ferries.py --include-drivetime   # full pipeline incl. OSRM
python3 scripts/refresh_ferries.py --only manual merge   # quick re-seed
python3 scripts/refresh_ferries.py --skip gtfs           # skip the slow GTFS pulls
```

Logs are appended to `logs/refresh_ferries.log`.

## 5. Terminal-mapping rules

Terminals are the join key between routes and islands. The matching rules are:

1. If the OSM relation has a node tagged `amenity=ferry_terminal`, use its lat/lon and `name`/`name:*` tags.
2. Otherwise, use the first or last node of the first/last `way` in the relation, prefixed with the route's `name` as a fallback.
3. Match each terminal to the nearest island within **1 km** (Haversine). Beyond that, `islandId` stays `null` (the terminal is on mainland or on a large island like Great Britain itself).
4. Mainland-side terminals (`islandId == null`) get `driveTimeMinutes` populated by `scripts/compute_drive_times.py` (OSRM, via `curl` to dodge Python's TLS issue with the public OSRM server).
5. Cultural names (`gd / cy / ga / gv / kw / fr`) are merged via `scripts/enrich_terminal_names.py` against a hand-curated map. Surfaces in the ferry card as `<small>An t-Òban</small>` under "Oban".

Many-to-many handling: a single island may be served by several terminals (Mull has Craignure + Fishnish + Tobermory). The UI groups by `from`+`to` and surfaces every route. A single terminal may serve many operators (Oban is the source of ~7 routes); routes are deduped on `(operatorId, from.terminalId, to.terminalId)`.

## 6. UI surface

- `loadFerries()` + `loadCauseways()` in `app.js` — lazy-fetched on first island click, cached on `state`.
- `renderFerries(island)` — emits the "How to get there" block. Each route is a `.ferry-card` with operator logo, route label, duration, frequency / seasonality / type pills, verified/stale badge, drive-time pills, Trainline + Discover Cars affiliate links, and a "Book ↗" CTA.
- `drawFerryRoutesOnDetailMap()` — dashed polylines + terminal markers on the detail map.
- Sidebar — `⛴` icon next to ferry-accessible islands (`state.ferryIslandIds.has(...)`).
- Chatbot — `parseChatQuery` recognises "ferries to …", "ferry from Oban", "summer car ferries to the Hebrides"; scored against ferry-accessible islands only when intent is detected.
- Itinerary builder — `?trip=startId,endId` URL param triggers Dijkstra over `state.ferryGraph` and renders an `.itinerary-banner` at the top of the page.
- SEO landing pages — `scripts/generate_ferry_landing_pages.py` emits 12 regional pages (Hebrides, Orkney, Isle of Wight, Scillies, CalMac, IoM, Channel Islands, Aran, etc.) under `ferries/`, each with `TouristTrip` JSON-LD per route.

## 7. Known limitations

- **OSM geometries are indicative.** Dashed lines + caption.
- **Vessels swap mid-season.** `vessel[]` is informational, not authoritative.
- **No affiliate program for the big UK operators.** Trainline + Discover Cars capture the train-to-port / car-hire-at-port adjacent value; all such links carry `rel="sponsored"` and an `(affiliate)` micro-tag.
- **`compute_drive_times.py` uses the public OSRM demo server**, which is not for production traffic. The script throttles to 0.4 s between requests; the orchestrator skips this stage by default. For a heavier run, deploy a private OSRM or switch to OS Linked Identifiers.
- **Schedules drift.** Always cross-reference the operator's own timetable page (the `Book ↗` button), especially for stale-flagged routes.
- **GTFS season-change gaps.** When `validTo` lapses mid-month, the route reverts to operator-URL-only until the next refresh.
